Product and technical plan

Privacy First Weekly Planning Notebook

A web application that turns a paper weekly planning spread into a fast, private, encrypted planning workflow: weekly direction, weekly todos, day assignment, daily notes, history, and Sunday reminders.

Product Shape Weekly planner with notebook-like daily notes
Privacy Model Client-side end-to-end encryption with vault passphrase and recovery key
Stack Angular, Angular Material, Tailwind, Express, PostgreSQL, TypeScript
Deployment Dockerized app hosted on Railway
North Star Scope UX Flow Privacy Architecture Data API Deployment Roadmap Risks

North Star

The app should feel like opening a private weekly notebook, not managing a generic productivity database.

Core Promise

Help users set weekly direction, distribute work across days, and capture daily notes while keeping private content unreadable to the service operator.

Primary Differentiator

The combination of weekly spread, task outcome tracking, daily notes, history, and true privacy gives the product a specific identity.

Design Constraint

The planner must be faster than paper for common actions. No heavy drawing editor in V1.

Scope

V1 focuses on planning and encrypted notes. Advanced visual note-taking is intentionally postponed.

V1 Includes

  • Social login and email/password login.
  • Vault passphrase unlock after authentication.
  • Recovery key generated during vault setup.
  • Weekly plan with ISO week number and date range.
  • Big picture direction for the week.
  • Weekly todo list.
  • Assign weekly tasks to specific days.
  • Add ad hoc daily tasks.
  • Mark tasks as completed or skipped.
  • Skipped reason visible in the UI.
  • Simple daily notes.
  • Calendar/history for previous weeks.
  • Sunday planning reminder by email, configurable after authentication without vault unlock.

V1 Excludes

  • Free drawing.
  • Boxes, arrows, dotted lines, and movable canvas objects.
  • Native mobile apps.
  • Complex rich-text editor features beyond basic formatting.

Weekly Planning

Sunday reminder brings the user to next week's planning view. The user sets direction, creates weekly tasks, and assigns tasks to days.

Daily Use

Each day shows date, weekday, assigned tasks, ad hoc tasks, and a simple notes area. The default interaction should be quick entry.

Reflection

Previous weeks show completed work, skipped tasks with reasons, notes, and direction. This is history, not analytics-heavy performance scoring.

Privacy And Encryption

Login proves identity. Vault passphrase or recovery key unlocks private content.

Non-negotiable rule: the backend must never receive plaintext task titles, notes, weekly direction, skipped reasons, the vault passphrase, the recovery key, or the decrypted vault key.

Vault Setup

  1. User authenticates with email/password or social login.
  2. Browser asks user to create a vault passphrase.
  3. Browser generates a random 256-bit vault key.
  4. Browser derives a wrapping key from the passphrase using Argon2id.
  5. Browser encrypts the vault key with that wrapping key.
  6. Browser generates a random recovery key and displays it once.
  7. Browser derives a second wrapping key from the recovery key using Argon2id.
  8. Browser encrypts the same vault key with the recovery wrapping key.
  9. Server stores encrypted vault key wrappings, salts, nonces, and KDF parameters.

Forgot Passphrase

  1. User logs in to the account.
  2. User chooses recovery key flow.
  3. Browser derives recovery wrapping key from the recovery key.
  4. Browser decrypts the vault key.
  5. User creates a new vault passphrase.
  6. Browser re-wraps the vault key with the new passphrase.
  7. Browser rotates the recovery key and shows a new one.
  8. Old recovery wrapping is marked used or revoked.

Encrypted Week Payload

Store the user's actual planner content inside one encrypted payload per week for V1. This keeps privacy simple and avoids leaking task counts or note lengths at a fine-grained level.

  • bigPictureDirection
  • weeklyTasks
  • dailyPlans
  • dailyTasks
  • dailyNotes
  • taskStatuses
  • skippedReasons

Plain Metadata

Keep metadata minimal. Plain week dates enable fast lookup and reminders, but they reveal usage patterns. If maximum privacy becomes a requirement, move more metadata into encrypted payloads later.

  • User id and login identities.
  • Vault id and crypto version.
  • Week start date, ISO week, and year.
  • Account-level notification schedule and timezone.
  • Creation/update timestamps.

API Surface

Backend endpoints move ciphertext and metadata. They do not understand private content. Routes use RESTful nouns: the HTTP method decides the action, the path identifies the resource, and route paths avoid verbs.

Module Example Endpoints Purpose
auth POST /sessions, GET /sessions, DELETE /sessions/:sessionId, GET /oauth/providers/:provider/authorizations Account authentication through local credentials and social providers.
vault POST /vaults, GET /vaults/:vaultId/key-wrappings, GET /vaults/:vaultId/key-wrappings/:keyWrappingId, PUT /vaults/:vaultId/key-wrappings/:keyWrappingId Store encrypted vault key wrappings and recovery state.
weeks GET /years/:year/weeks, GET /years/:year/weeks/:isoWeek, PUT /years/:year/weeks/:isoWeek Read and write encrypted weekly planner records.
notifications GET /users/:userId/notification-settings, PUT /users/:userId/notification-settings Manage Sunday reminder settings and email delivery preferences after authentication, without requiring vault unlock.
users POST /users, GET /users/:userId, PATCH /users/:userId, DELETE /users/:userId Create accounts, manage profiles, and handle account lifecycle.

Roadmap

Build privacy and core planning first, then expand editing power only after the planner is useful.

Foundation

Repository setup, TypeScript configs, Angular shell, Express shell, PostgreSQL connection, Dockerfile, health check, and CI.

Authentication

Email/password login, social login, Passport.js strategies, session or token handling, account profile, and protected API routes.

Vault Encryption

Vault setup, Argon2id derivation, AES-GCM encryption, passphrase unlock, recovery key setup, recovery flow, and passphrase rotation.

Planner MVP

Current week view, ISO week notation, weekly direction, weekly todos, daily assignment, ad hoc daily tasks, notes, task completion, skipped reasons, and persistence.

Calendar And Reminders

Previous week navigation, calendar history, Sunday reminders, timezone handling, and email delivery.

Polish And Launch

Responsive layout, accessibility checks, onboarding copy, recovery-key warnings, privacy policy, deployment hardening, backups, logs, and beta launch.

Risks And Decisions

The hard parts are privacy UX, metadata leakage, and keeping the planner fast.

Key Risks

  • Users losing both passphrase and recovery key means old data cannot be recovered.
  • Client-side encryption makes search, analytics, and server-side processing much harder.
  • Plain metadata can still reveal usage patterns.
  • Argon2id in browser requires a vetted WASM implementation and careful performance tuning.
  • Sunday reminders must avoid exposing private content in email.
  • Too much rich text or drawing scope can delay the planner MVP.

Decisions Locked For V1

  • Use Angular Material, not React MUI.
  • Use simple text notes in V1.
  • Use client-side E2EE for private planner content.
  • Require a vault passphrase for all users, including social login users.
  • Keep notification settings account-level, requiring authentication but not vault unlock.
  • Generate a recovery key during setup.
  • Use a modular monolith backend.
  • Dockerize and deploy to Railway.

Open Technical Decisions

  1. ORM choice Prisma is ergonomic and mature; Drizzle is lighter and SQL-oriented. Pick one before schema work starts.
  2. Session strategy Use secure HTTP-only cookie sessions for web-first simplicity, or short-lived access tokens plus refresh tokens if future API clients are expected.
  3. Encrypted payload granularity One encrypted week blob is simpler and leaks less structure. Smaller encrypted records allow partial updates but leak more metadata.
  4. Basic note formatting Start plain text. Add bold/color only if it does not complicate encryption, editing, or mobile ergonomics.
